# Milestone 3: subagents and outside sessions

Read `CLAUDE.md` and `docs/ARCHITECTURE.md` first. The contract is `packages/shared/protocol.js` (**v3**): every M3
method, event and type is already in it (`Subagent`, `ActivityEntry`, `ExternalSession`, `subagents.list`,
`activity.list`, `external.list`, `external.takeOver`, events `subagent.updated`, `activity`, `external.changed`,
`AgentStatus.subagents` / `askedBy`, error `still_working`, hook `SubagentStart`). **Don't change it.** If you need
something it lacks, work around it and say so in your final report.

Each track works in its own git worktree on its own branch (`m3-<track>`), made from `m3`. Stay inside your files.
Where you must touch a shared file, keep the change small and say so in your report.

## What M3 is for

1. **See every subagent a session starts.** When Main hands work to helper agents (the Agent / Task tool), each one
   shows up under its session with a **title** (the short description Claude gave it, e.g. "Find token call sites"),
   its type (🔭 Explore, 📐 Plan, 🔧 General, ...), its state, and what it is doing right now.
2. **A full activity log, without spending tokens.** Everything a session and its subagents do (prompts, every tool
   call with its command / file, how long it took, errors, permission prompts, subagent start / end with summary) is
   logged by the core from Claude Code's **hook events** (and for outside sessions, by reading Claude's transcript
   files). No model call is ever made for this.
3. **Outside sessions.** Claude Code sessions running on this computer that CC-Dashboard did not start (a terminal,
   VS Code, JetBrains...) appear as view-only tiles with their status and activity. **Take over** ends the outside
   process and reopens the same conversation inside the app (`claude --resume`), where it becomes a normal agent.

## What real Claude Code reports (2.1.x, verified)

`tests/fixtures/hooks/subagent-background.jsonl` holds the real hook payloads of one session that started one
background subagent (paths replaced with `<CWD>` etc.). In short:

- `PreToolUse` with `tool_name: "Agent"` (older versions: `"Task"`): `tool_input.description` (the title),
  `tool_input.subagent_type`, `tool_input.prompt`, maybe `tool_input.run_in_background`; `tool_use_id`.
- `PostToolUse` of that Agent call: for a background agent it comes at once with
  `tool_response: { isAsync: true, status: "async_launched", agentId, description, ... }`; for a foreground agent it
  comes when the subagent is done.
- `SubagentStart`: `agent_id`, `agent_type` (no description).
- Every `PreToolUse` / `PostToolUse` / `PermissionRequest` **inside** a subagent carries `agent_id` and `agent_type`.
  Without `agent_id` the event is the session's own.
- `SubagentStop`: `agent_id`, `agent_type`, `agent_transcript_path`, `last_assistant_message`.
- `Stop` (and `SubagentStop`) carry `background_tasks: [{ id, type: "subagent", status: "running", description,
  agent_type }]`: the subagents still running in the background, with their titles.
- When a background subagent finishes, Claude starts a new turn by itself: `UserPromptSubmit` whose prompt starts
  with `<task-notification>` (it is not the user typing).
- On disk, next to the session transcript `<projects>/<dir>/<sessionId>.jsonl`, each subagent has
  `<sessionId>/subagents/agent-<agentId>.jsonl` (its own transcript, `isSidechain: true`) and
  `agent-<agentId>.meta.json` = `{ agentType, description, toolUseId, spawnDepth, requestShape: "background"|...,
  finished }` (sample: `tests/fixtures/sessions/subagents-meta/`).
- Running sessions: `<claude config dir>/sessions/<pid>.json` = `{ pid, sessionId, cwd, startedAt, procStart, version,
  kind: "interactive", entrypoint, name, status: "busy"|"idle"|..., updatedAt, statusUpdatedAt, ... }` (sample:
  `tests/fixtures/sessions/registry-sample.json`). This is Claude's internal format: parse it defensively, skip what
  you don't understand, never crash on it. The claude config dir is `CLAUDE_CONFIG_DIR`, else `~/.claude`.
- Sample transcripts (only user / assistant lines kept): `tests/fixtures/sessions/main-transcript.jsonl` and
  `agent-ae0d14e7ad2db2bf5.jsonl`.

## Subagents track (core): what to build

1. **Log every hook event as `ActivityEntry` lines** (`activity.onHook`, called before the status update):
   SessionStart → `session_start` (text = source) · UserPromptSubmit → `prompt` (a `<task-notification>` prompt →
   `notice` "Subagent finished: <title>") · PreToolUse → `tool` · PostToolUse → `tool_done` / `tool_error` (with `ms`
   from `duration_ms`, else measured by `tool_use_id`) · PermissionRequest → `permission` · Stop → `turn_end` (text =
   start of `last_assistant_message`) · SubagentStart → `subagent_start` (text = title, type) · SubagentStop →
   `subagent_end` (text = summary) · Notification → `notice` (skip idle reminders) · SessionEnd → `session_end`.
   `subagentId` = payload `agent_id` or `''`. `detail` with `summarizeTool` from status.js. Caps: detail 300,
   text 500. Never store tool responses or file contents.
2. **Titles.** Queue every Agent/Task `PreToolUse` (description, subagent_type, tool_use_id, run_in_background). On
   `SubagentStart` take the oldest queued call of the same type (else the oldest); if none, read the subagent's
   `meta.json` (`<dirname(transcript_path)>/<session_id>/subagents/agent-<agent_id>.meta.json`; it may not exist yet,
   so try again on that subagent's next event), else `background_tasks` of a later Stop/SubagentStop, else the
   type's label (`SUBAGENT_TYPES`) or the type itself. A later PostToolUse(Agent) with `tool_response.agentId`
   corrects the pairing.
3. **Subagent state** (`Subagent`): running → done on SubagentStop; `stopped` when the session ends / is stopped /
   the core restarts with it running; `failed` when the Agent call's PostToolUse or task notification says so.
   `tool` / `detail` while one of its tools runs; `counts`; `needsYou` + `AgentStatus.askedBy` while a permission
   prompt from it is up (cleared when answered, approved, denied or the prompt goes).
4. **Parent status** (status.js / core.js): a subagent's tool events must not overwrite the session's own `tool` /
   `detail` and don't count in its `counts.tools`; `AgentStatus.subagents = { running, total }`; after `Stop`, while
   background subagents still run, the state stays `working` with detail "N subagents running", and turns `idle`
   when the last one ends (unless a new turn started). The "done" notification for a long turn waits for them too.
5. **Persistence**: `<CC_HOME>/activity/<agentId>.jsonl` (append, batched ≤ 250 ms; flushed on shutdown), seq
   continues across restarts; keep the last 1000 entries in memory, older pages from the file (`activity.list`
   `before`); when a file passes 2 MB rewrite it with its last 5000 entries (atomic). Subagents survive a restart
   (rebuild from the log or a small `<agentId>.subagents.json`). `agents.remove` deletes the files. A resumed
   agent continues the same log.
6. **Events**: `activity { agentId, entries }` batched (≤ 100 ms), `subagent.updated` on each change (coalesced).
7. **fake-claude**: a prompt with `subagents:<n>` (and `bg` for background) fires the same sequence as the fixture,
   including `meta.json` files, so core tests and e2e can run it without real Claude.

## Outside track (core): what to build

1. **Find sessions**: watch `<claude config dir>/sessions/` (fs.watch + poll every 2 s; `CC_EXTERNAL_POLL_MS` for
   tests). Keep a session if its JSON has a number `pid`, string `sessionId` and `cwd`, the pid is alive
   (`process.kill(pid, 0)`, EPERM = alive), and it is not one of our agents (same `sessionId` as any Agent). State:
   `busy` → working, `idle` → idle, anything that means waiting / permission → needs_you, else unknown.
   `spaceId` = the space whose path equals or contains cwd (case-insensitive and either slash on Windows).
2. **Activity from transcripts** (`transcript.js`, pure parsing + a small tailer): find
   `<config>/projects/*/<sessionId>.jsonl` (try Claude's folder name for cwd first, then scan), read it incrementally
   (byte offset; tolerate a half-written last line), turn assistant `tool_use` → `tool`, user `tool_result` →
   `tool_done` / `tool_error`, real user text → `prompt`; subagents from `subagents/agent-*.meta.json` (title =
   description, type = agentType, `finished` → done, `requestShape: "background"`) and their own jsonl (lines get
   that `subagentId`). In memory only (the transcript is the record), last 2000 entries per session. Only tail live
   sessions; read faster (1 s) while one is working, else 3 s.
3. **Events**: `external.changed` (coalesced, only when something changed), `activity`, `subagent.updated`.
4. **external.takeOver**: re-read the registry file (same pid and sessionId), confirm the process is that Claude
   (win32: `tasklist /FI "PID eq <pid>" /FO CSV /NH` image name; linux: `/proc/<pid>/cmdline`; macOS:
   `ps -p <pid> -o command=`; it must look like claude/node), refuse `still_working` if it is working and no
   `force`, end it (win32: `taskkill /PID <pid> /T /F`; else SIGTERM, then SIGKILL after 3 s), wait until it is
   gone (≤ 10 s, else `not_allowed`), then create the agent (space: given, matching, or a new one for cwd; name:
   given, the session name, or the folder name) with that `sessionId` and launch it with `--resume` in its cwd.
   It returns the Agent and the session leaves the outside list at once.
5. **Tests** with a temp `CLAUDE_CONFIG_DIR`: registry files pointing at a live child process (a tiny node script
   whose path contains "claude"), fixture transcripts, takeOver against `tests/fake-claude.js`.

## Activity UI track: what to build

- **Activity drawer** (right side of the main area, ~380 px; an overlay below ~1100 px window width), shown when
  `S.activityFor` is set (`ctx.openActivity(agentId, subagentId?)`), works for agents and `ext:` sessions.
  Header: session name, role badge (or 👁 Outside), close (Esc). A list: "Session" first, then every subagent
  (type emoji + **title**, state: running spinner / ✓ done / ✗ failed / ■ stopped, tools count, duration, the tool
  it runs now, "needs you"). Clicking one filters the feed; "All" shows everything. The feed: newest at the
  bottom, one line per entry (time, who, icon per kind, tool + detail, duration, errors in red), live via
  `ctx.onActivity`, follows the bottom unless the user scrolled up ("Jump to latest"), "Load older" through
  `activity.list { before }`. Keep it light for long logs (render at most ~500 lines).
- **Subagent strip** in each grid tile (under the header): chips for running subagents (emoji, title, current
  tool), "+N" when more, "✓ N" done count, a needs-you chip stands out. Click → drawer filtered to it.
- **Sidebar**: a small "N running" subagent badge on the agent card. **Approval card**: "asked by <emoji> <title>"
  when `status.askedBy` is set. **Agent menu**: "Activity". **Shortcut**: `Ctrl+Shift+Y` toggles the drawer for
  the focused agent (add it to logic.js `shortcutFor` + its unit test; plain Ctrl+Y stays with the terminal).
- The renderer can't import protocol.js: copy `SUBAGENT_TYPES` into `activity-logic.js` with a unit test that
  checks it matches (like roles.test.js).

## Outside UI track: what to build

- **Grid**: after a space's agents, its outside sessions as view-only tiles: 👁 "Outside" badge, name, where it
  runs ("VS Code", "Terminal", "JetBrains" from `entrypoint`), state dot, current tool, the last ~6 activity lines
  (`activity.list` + `ctx.onActivity`), subagent count, buttons **Activity** (`ctx.openActivity(id)`) and
  **Take over**. They count as tiles for the 4-visible / scroll rules.
- **Take over dialog**: "This ends the session in <VS Code> and reopens the same conversation here, with its
  terminal. Anything it is doing right now stops." If it is working (or the core answers `still_working`): a
  warning and the button becomes "End it and take over" (`force: true`). On success open the new agent, toast.
- **Sidebar**: under each space, after its agents, "Outside the app (N)" with compact view-only cards (collapsible,
  remembered per window). Sessions outside every space: an "Other folders" group at the bottom, each with
  **Add as space** (`spaces.add { path: cwd }`).
- **Board**: outside sessions as cards in their state's column with the 👁 badge, no actions but Activity /
  Take over. **Inbox**: an outside session that waits for you shows as a row "waiting in VS Code" (no Allow/Deny:
  the app has no terminal for it) with Take over.
