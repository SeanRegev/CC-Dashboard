# Milestone 4: real context %, usage meter, subagent cards

Read `CLAUDE.md`, `docs/ARCHITECTURE.md` and `docs/M3.md` (how tracks work) first. The contract is
`packages/shared/protocol.js` (**v4**). Every M4 method, event and type is already in it. **Don't change it.** If you
need something it lacks, work around it and say so in your final report.

Each track works in its own git worktree on its own branch (`m4-<track>`), made from `m4`. Stay inside your files.
Where you must touch a shared file, keep the change small, keep it in its own function or block, and say so in your
report.

## What M4 is for

1. **The context % is right.** It shows Claude's own number. Today a session with a 1M window at 10% shows 49%,
   because `usage.js` assumes 200k. The "75k tokens" next to the bar is the session's total, not the context size,
   so the two numbers don't agree.
2. **A usage meter for the account:** "5h 62% · resets 16:20 / week 31%" in the top bar, plus a Usage view with cost
   and tokens per agent, per space and per day.
3. **Subagents get cards of their own** in the sidebar, the grid and the Terminals view, each with its title and model.
4. **0.3 follow-ups:** Allow/Deny when the prompt header has scrolled away, a stricter Take over check, and lighter
   tailing of outside sessions.
5. **Indexer trial (research only):** does a code index make agents cheaper or faster here? Adopt, build or skip.

## What real Claude Code reports (2.1.332, verified)

**Status line.** If the settings say `statusLine: { type: "command", command }`, Claude runs that command on each
update (interactive sessions only) with a JSON snapshot on stdin, and shows what it prints. Our `--settings` file
outranks the user's settings, so registering ours **hides the user's own status line** unless we run it for them.

- `tests/fixtures/statusline/startup.json`: the first update, before any reply. `context_window.context_window_size`
  is already there (1000000 on this account), but `used_percentage`, `remaining_percentage` and `current_usage` are
  `null`, and `rate_limits` is missing.
- `tests/fixtures/statusline/sample.json`: after a reply. `used_percentage` 10, `current_usage {input_tokens,
  output_tokens, cache_creation_input_tokens, cache_read_input_tokens}`, `total_input_tokens` / `total_output_tokens`
  (whole session), `cost.total_cost_usd`, `rate_limits.five_hour` / `seven_day {used_percentage, resets_at}` with
  `resets_at` in epoch **seconds**, `model {id, display_name}`, `session_id`, `transcript_path`, `cwd`, `version`.
- Claude adds fields over time (`prompt_cache`, `thinking`, `effort`, `workspace.repo`, ...). Read what you need,
  ignore the rest, and never crash on a missing or `null` field.
- On a subscription, `total_cost_usd` is an **API-equivalent estimate**, not a bill. The UI must say so.

**Subagents.** `<transcript dir>/<sessionId>/subagents/agent-<id>.meta.json` has `model` (as well as `description`
and `agentType`). The Agent tool's `tool_input.model` can also name one (`"haiku"`, `"sonnet"`, ...). Lone
`SubagentStop`s with an empty `agent_type` (hidden helpers) are already ignored.

## A. Status line + context fix: what to build

This runs inside **every** agent session. A bug here breaks all of them, so be careful and test the edges.

1. **Register it.** `buildSettings()` adds `statusLine: { type: "command", command: "\"<home>/cc-statusline.cmd\"" }`
   (`.sh` elsewhere). Reuse the `cc-hook` launcher pattern and its quoting: `ELECTRON_RUN_AS_NODE=1` only for the relay,
   forward slashes, works from both cmd.exe and Git Bash. The relay is `core/src/statusline-relay.js`: no
   dependencies, starts fast.
2. **The relay.** Read stdin and POST it to `${CC_CORE_URL}/statusline?agent=${CC_AGENT_ID}` with `x-cc-token` (2 s
   timeout, errors ignored). At the same time, produce the line to print:
   - **The user's own status line, unchanged.** Find their effective `statusLine` the way Claude does, without ours:
     `<cwd>/.claude/settings.local.json`, then `<cwd>/.claude/settings.json`, then `<CLAUDE_CONFIG_DIR or
     ~/.claude>/settings.json` (and managed settings, if you can find them cheaply). The core resolves this when it
     launches the agent and passes it to the relay (e.g. an env var with `{command, padding}`), so the relay does no
     searching. Run the command with the **same stdin** and the way Claude would run it (check how Claude runs
     status-line commands on Windows, don't assume), then print its stdout as is. Its exit code and stderr pass
     through as well as they can.
   - **No status line of their own:** print a short default, e.g. `Haiku 5.5 · ctx 10% · 5h 62%`. No colours needed.
   - The relay prints **nothing else**, never fails (exit 0 unless the user's command failed), and is done well
     within Claude's patience. A dead or slow core must never delay the line.
   - Without `CC_AGENT_ID` (a claude the core did not start), just run the user's line or the default.
3. **The core side** (`statusline.js`). `handle(agentId, payload)`: keep the latest per agent and apply **at most
   once a second per agent** (trailing update, so the last one always lands).
   - `AgentStatus.usage`: `source 'statusline'`, `contextWindow = context_window_size`, `contextPct =
     used_percentage` when it is a number, `context` = the sum of `current_usage` input-side fields,
     `costUsd = cost.total_cost_usd`, `model = model.id`. Before the first reply (`used_percentage: null`) keep the
     transcript estimate but take the window from the status line. `total` stays what it was (input + output +
     cache writes); don't change its meaning.
   - The account `Usage.limits`: from the freshest update that has `rate_limits` (`resets_at` × 1000).
     `fromAgentId` = that agent.
   - Totals: `byAgent`, `bySpace`, `byDay` from **deltas** of `total_cost_usd`, `total_input_tokens`,
     `total_output_tokens` between updates of the same session. A value that goes down (a new process, `--resume`)
     starts a new baseline; never count anything twice. `byDay` uses the local date.
   - Persist `<CC_HOME>/usage.json` (atomic write, debounced, flushed on shutdown): byAgent (with name and spaceId),
     bySpace, byDay (keep about 90 days), the last limits, and the windows seen per model id (for the fallback below).
   - Broadcast `agent.status` through the normal `core.update()` path, and `usage.changed` at most once a second.
4. **Fix `usage.js`** (the transcript fallback, used before the first update and for agents without a status line):
   no hard-coded 200k when the window is known. Order: the last status-line window for this agent; else the window
   last seen for that model id (from `usage.json`); else `[1m]` in the agent's model; else 1M when the context is
   already over 200k; else 200k. `source: 'transcript'`.
5. **Tests**: both fixtures; nulls, missing fields, junk; the 1 s throttle; deltas across a restart / resume;
   `usage.json` survives a core restart; the relay prints the user's line (a fake user command that echoes part of
   its stdin), the default, and stays quick when the core is down. Extend `tests/fake-claude.js` so it reads the
   `statusLine` command from its `--settings` file and runs it with a sample JSON (e.g. on a prompt
   `statusline:<pct>`, and once at start like real Claude). Use a temp `CLAUDE_CONFIG_DIR` for the user settings.

## C. Subagent cards: what to build

- **Sidebar**: under each agent card, its subagents as indented child cards: type emoji, **title**, model
  (`modelLabel`, e.g. "Haiku 4.5"), current tool, elapsed time, state (running spinner / ✓ / ✗ / ■, needs-you stands
  out). Collapsible per session (remembered per window, like the "Outside the app" group). Finished ones fold into one
  "✓ N done" line that expands.
- **Grid**: a row of small subagent cards (not terminals) under the parent tile; it replaces the M3 chip strip. It
  must still fit the 4-visible / scroll rules and look right at 1024×768.
- **Terminals view**: a subagent bar in `.pane-sub` under the pane header (already mounted; return null to hide it).
- **Clicking** a card opens the activity drawer filtered to that subagent (`ctx.openActivity(agentId, subagentId)`).
  Cards are focusable buttons with readable labels.
- **`Subagent.model`** in `activity.js`: from `meta.json` `model`, else the Agent call's `tool_input.model`, else
  leave it out. For outside sessions, the same from `transcript.js`. fake-claude writes `model` into its meta.json.
- Works for outside sessions too (`ext:` ids) where they show subagents.

## D. 0.3 follow-ups: what to build

1. **Allow/Deny without the header.** In a short grid tile the "Bash command" header can scroll off screen, so
   `prompt.js` can't read the prompt, and the app sends the user to the terminal. When the options are on screen but
   the header isn't, take `tool` and `detail` from the last `PermissionRequest` hook payload (`tool_name`,
   `tool_input`: command, file_path, url, ...) and still return a `PermissionPrompt`. The fingerprint must still
   change when the prompt changes. Add screen fixtures for it.
2. **Take over identity check.** A `node` / `bun` process counts as Claude only when it runs Claude's script: its
   path contains `@anthropic-ai/claude-code`, or the script's name is `claude` (`claude`, `claude.js`, `claude.cmd`,
   `cli.js` inside that package). Not just "claude" anywhere on its command line (`node my-claude-notes.js` is not
   Claude). `claude.exe` itself still counts. Tests for all three platforms' parsers.
3. **external.js**: stop tailing finished subagents whose files haven't changed (size and mtime), and stop
   re-reading meta.json files that haven't changed. Test that a finished subagent is not read again.

## B. Usage UI: what to build (against the mock from wave 0)

- **Top-bar meter** (`usageMeter`): `5h 62% · resets 16:20 / week 31%`. Amber at 75%, red at 90%. Tooltip: "as of
  HH:MM" and which agent reported it (`fromAgentId` → its name). Nothing when `limits.updatedAt` is 0. If `resetsAt`
  has passed, say so rather than show an old %. It must fit the top bar at 1024 px next to the 7 view buttons.
- **Usage view** (`Ctrl+Shift+U`): cost and tokens per agent, per space and per day (bars or a table), labelled
  "API-equivalent estimate". Removed agents show under their saved name.
- **Context gauge** (`contextGauge`): `98k / 1M (10%)`: context / contextWindow (contextPct). The number and the bar
  must agree. A transcript estimate looks like one (e.g. "~"). Use the same text in grid tiles and board cards. Fix the
  misleading "75k tokens" foot item (it is the session total, label it so, or show the cost estimate instead).
- **New agent dialog** (`limitWarning`): a warning when the 5-hour limit is at 90% or more.
- Check both themes, and 1024×768 (Windows CI clamps the window to that).
